## 03. Plan — Match LibreChat YAML Behavior (Developer Implementation Plan)

This is the **developer-focused implementation plan** for modifying **T3Chat** (`D:/Work/rust/T3Chat`) to match **LibreChat** configuration behavior and schema defined by `librechat.yaml`.

-   Source of truth for expected behavior: LibreChat `librechat.yaml` docs and implementation in `D:/Work/nodejs/LibreChat`.
-   **No backward compatibility required** (no prior versions), so we can replace the existing `t3chat.yaml` contract.
-   **Database schema**: only change DB schema if absolutely necessary. If we do, **merge changes into** `server/migrations/00000000000000_diesel_initial_setup/{up.sql,down.sql}` (do not create new migrations).

---

## Goals (behavioral parity)

-   **Primary config contract**: adopt LibreChat-style `librechat.yaml` key names and nesting.
-   **Non-fatal config**:
    -   Missing config file must **not** crash startup.
    -   Invalid config file must **not** crash startup; it should be ignored with clear notices.
-   **Strict validation when config exists**:
    -   If the YAML exists but fails schema validation, treat as **ignored** (fallback to defaults) and emit notices.
-   **Lazy placeholder resolution**:
    -   Preserve `${ENV_VAR}` placeholders at load time.
    -   Only resolve when the value is actually used.
    -   Missing env vars should **disable the affected provider/feature** with notices (not crash).

---

## Current State (T3Chat)

-   Config loader is currently **fail-fast** for env interpolation and parses `t3chat.yaml` into `T3ChatConfig`:
    -   `server/src/config/mod.rs` interpolates `${ENV_VAR}` and returns `MissingEnvVar`.
    -   `server/src/config/t3chat.rs` enforces `At least one provider must be configured`.
-   Startup config and model catalog are derived from `T3ChatConfig`:
    -   `server/src/api/v1/config/startup.rs`
    -   `server/src/api/v1/config/models.rs`
    -   `server/src/ai/model_catalog.rs`
-   AppState holds `t3_config: Arc<T3ChatConfig>`.

This plan replaces that flow with a LibreChat-style config module and “config may be absent/ignored” semantics.

---

## High-level architecture

### New configuration flow

1. **Locate config source** (file path or URL): `CONFIG_PATH` first, otherwise `./librechat.yaml`.
2. **Load raw YAML** (read file or fetch URL). If missing/unreadable → treat as “no config”.
3. **Parse + strict validate** into `LibreChatConfig`.
    - If parse/validation fails → ignore config.
4. **Build DerivedAppConfig** (internal runtime config) from `LibreChatConfig` + defaults.
5. **Resolve placeholders lazily** at point-of-use:
    - Provider API keys, base URLs, headers, and request params.
6. **Serve startup config** (sanitized, non-secret) and **model catalog** to the client.

### Key types to introduce

-   `LibreChatConfig`: serde-deserializable representation of `librechat.yaml`.
-   `ConfigSource`: enum describing where config came from.
-   `ConfigNotices`: structured notices (warning/info) surfaced to `/api/v1/config/*`.
-   `DerivedAppConfig`: the **only** type the rest of the server reads.

### B1. Implement LibreChat YAML schema in Rust (`LibreChatConfig`)

-   **Create file**: `server/src/config/librechat.rs`

Implementation details:

-   Use `serde` with strictness:
    -   Prefer `#[serde(deny_unknown_fields)]` on structs where feasible.
    -   Use `serde_json::Value` for flexible objects like `headers`, `addParams`, `dropParams`, etc.
-   Use casing similar to LibreChat:
    -   `#[serde(rename_all = "camelCase")]` for most nested objects.
    -   Explicit `#[serde(rename = "openAI")]`, `#[serde(rename = "azureOpenAI")]`, etc. where LibreChat uses mixed keys.

Suggested minimal schema coverage for parity with current T3Chat behavior:

-   Root:

    -   `version: Option<String>`
    -   `interface: Option<InterfaceConfig>`
    -   `endpoints: Option<EndpointsConfig>`
    -   `modelSpecs: Option<Vec<ModelSpec>>` (or struct wrapper if LibreChat uses one)
    -   `registration`, `actions`, `cache` (parse now, implement later)

-   Endpoints:
    -   Built-ins: `openAI`, `anthropic`, `google` (parse and wire)
    -   `custom: Vec<CustomEndpoint>` (parse and wire as “OpenAI-compatible”)
    -   Parse-but-ignore for now: `bedrock`, `azureOpenAI`, `assistants`, `agents` (keep strict parsing consistent with chosen coverage)

Acceptance:

-   `librechat.example.yaml`-compatible documents parse cleanly.

### B2. Implement LibreChat-like loader semantics (`load_config()` becomes non-fatal)

-   **Update**: `server/src/config/mod.rs`

Replace the current behavior:

-   Current: missing env var referenced in YAML → `Err(MissingEnvVar)`.
-   Target:
    -   Missing file → `Ok(LoadedConfig { config: None, notices: [warning], ... })`
    -   Parse/validation failure → `Ok(LoadedConfig { config: None, notices: [error/warn], ... })`

Proposed structs:

-   `pub struct LoadedConfig { pub config: Option<LibreChatConfig>, pub metadata: ConfigMetadata }`
-   `pub struct ConfigMetadata { pub source: ConfigSource, pub notices: Vec<ConfigNotice> }`
-   `pub enum ConfigSource { Missing { expected: PathBuf }, File { path: PathBuf }, Url { url: String } }`

Path resolution (no compatibility required):

-   If `CONFIG_PATH` is set:
    -   If starts with `http://` or `https://` → fetch.
    -   Else treat as filesystem path.
-   Else default to `./librechat.yaml`.

Remote config fetch:

-   Add (if not already present) a small HTTP client with timeouts and size limits.
-   Failure to fetch counts as “no config” + notice.

### B3. Introduce lazy placeholder resolution utilities

-   **Create file**: `server/src/config/placeholders.rs` (or `server/src/config/resolve.rs`)

Requirements:

-   Do **not** interpolate the raw YAML string.
-   Provide a helper that can be called at point-of-use:
    -   `resolve_env_placeholders(s: &str) -> ResolvedString` where `ResolvedString` carries:
        -   `value: String` (placeholders resolved where possible)
        -   `unresolved: Vec<String>` (env var names still missing)

Provider enablement rule:

-   If an endpoint requires `apiKey` and it resolves to empty or still contains `${...}` → treat endpoint as **disabled** and emit a notice.

Notice de-duplication:

-   Ensure the same missing env var doesn’t spam logs; de-dupe by `(source, var_name, field_path)`.

### B4. Build a `DerivedAppConfig` from LibreChat config (+ defaults)

-   **Create file**: `server/src/config/app_config.rs`

Why:

-   The server should not “pull” from `LibreChatConfig` everywhere.
-   Centralize mapping + defaults + feature gating.

Contents:

-   `pub struct DerivedAppConfig`:
    -   `app_title: Option<String>`
    -   `interface: DerivedInterfaceConfig`
    -   `endpoints: Vec<DerivedEndpoint>` (each already validated for minimum required fields)
    -   `model_specs: Vec<DerivedModelSpec>`
    -   `notices: Vec<ConfigNotice>`

Mapping responsibilities:

-   Map LibreChat `endpoints.*` into T3Chat provider keys:

    -   `endpoints.openAI` → provider key `openai`
    -   `endpoints.anthropic` → `anthropic`
    -   `endpoints.google` → `google`
    -   `endpoints.custom[]` → unique provider keys (e.g. `custom:<name>` or the LibreChat `name`)

-   Preserve request-shaping fields where possible:
    -   `baseURL`, `apiKey`, `headers`, `addParams`, `dropParams`

Acceptance:

-   Derived config can be constructed even when `config == None` (pure defaults + notices).

### B5. Update model catalog build to use `DerivedAppConfig`

-   **Update**: `server/src/ai/model_catalog.rs`

Target behavior:

-   Allow an empty catalog when config is missing or no endpoints are enabled.
-   For each enabled endpoint:
    -   If it supports `models.fetch` semantics in LibreChat config, fetch where implemented.
    -   Otherwise fall back to configured `models.default` or an internal static list.

Notes:

-   Today `ModelCatalog::build(config: Arc<T3ChatConfig>, allow_empty: bool)` is wired from `main.rs`.
-   Change it to accept derived endpoints and already-resolved “fetch allowed” flags.

### B6. Refactor `AppState` and `main.rs` wiring

-   **Update**: `server/src/main.rs`

Replace:

-   `pub t3_config: Arc<config::t3chat::T3ChatConfig>`

With:

-   `pub app_config: Arc<config::app_config::DerivedAppConfig>`
-   `pub config_metadata: Arc<config::ConfigMetadata>` (or merge into `app_config.notices`)

Startup sequence:

1. `loaded = config::load_config()` (never fatal)
2. `app_config = DerivedAppConfig::from_loaded(loaded)`
3. `model_catalog = ModelCatalog::build(app_config.clone(), /*allow_empty*/ true)`

Important:

-   Do not `anyhow!()` on config load failures anymore.
-   Keep DB connection fatal (can’t run without DB).

### B7. Update config HTTP APIs to expose LibreChat-like shapes

-   **Update**: `server/src/api/v1/config/startup.rs`
-   **Update**: `server/src/api/v1/config/models.rs`

Recommended API contract (camelCase JSON):

-   `GET /api/v1/config/startup` returns:

    -   `appTitle`

-   `GET /api/v1/config/models` returns:
    -   `{ providers: { [providerKey: string]: ModelInfo[] } }`

Security:

-   Ensure `apiKey` and any secrets never appear.

### B9. Tests (backend)

Add tests focused on LibreChat parity:

-   **Config loader**:
    -   Missing file → `config == None`, contains notice.
    -   Invalid YAML → `config == None`, contains notice.
